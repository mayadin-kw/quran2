# تطبيق تسميع القرآن الكريم

تطبيق عربي ثابت الملفات، مناسب للنشر على GitHub Pages. يستخدم صفحات مصحف المدينة SVG الأصلية، ويشغّل نموذج FastConformer القرآني داخل المتصفح. لا يرفع الصوت الخام إلى Firebase.

## التشغيل والنشر

1. شغّل خادم ملفات محليًا من جذر المشروع، مثل `python3 -m http.server 8765`، ثم افتح `http://localhost:8765`. لا تعمل صلاحية الميكروفون عبر `file://`.
2. للنشر، ضع جميع ملفات المشروع في مستودع GitHub واختر الفرع والجذر في إعدادات **Pages**. المسارات نسبية، فتعمل كذلك تحت مسار مستودع فرعي.
3. يلزم HTTPS خارج `localhost` لاستخدام `getUserMedia()`.
4. في أول فتح يكون زر «تسميع» مقفلًا. يطلب التطبيق موافقة المستخدم قبل تنزيل حزمة التسميع كاملة، وحجمها الفعلي في `data/recitation-assets-manifest.json`. يشمل التنزيل صفحات المصحف الـ604 والنموذج ومحرك التشغيل، ثم تتحقق البصمات قبل تفعيل الزر. لا يبدأ هذا التنزيل تلقائيًا.
5. ملف المشفر `encoder.int8.onnx` أكبر من حد GitHub للملف الواحد، لذلك يجلبه بيان الحزمة من مستودع النموذج العام في Hugging Face ويحفظه محليًا في Cache Storage. النسخة المحلية في `assets/models/` مخصصة لبناء البيان والاختبار وتُستثنى من Git. بقية الموقع قابلة للنشر على GitHub Pages دون خادم تطبيق.

## بنية المشروع

- `assets/mushaf/`: صفحات SVG الـ604 من MushafDatabase، الإصدار V1.01.
- `assets/models/`: نموذج FastConformer ONNX ومفرداته.
- `assets/vendor/`: onnxruntime-web 1.30.0، مُضمَّن محليًا.
- `data/quran-index.json`: فهرس الصفحات والآيات والكلمات المستخرج من SVG.
- `data/recitation-assets-manifest.json`: قائمة كل الملفات الإلزامية وأحجامها وبصمات SHA-256.
- `js/download-manager.js` و`service-worker.js`: تنزيل الحزمة تدريجيًا، استكمال الملفات الناقصة، والتحقق من جاهزية العمل دون اتصال.
- `js/`: واجهة التطبيق، المصحف، الميكروفون، النموذج، المطابقة، التقرير، وFirebase.
- `scripts/`: جلب الأصول وإعادة بناء الفهرس.
- `tests/`: اختبارات الفهرس ومنطق التسميع.

لإعادة إنشاء الأصول، شغّل `python3 scripts/fetch_assets.py` أولًا، ثم `python3 scripts/build_index.py`، ثم `python3 scripts/build_manifest.py` بعد أي تغيير في الملفات الإلزامية. يجلب سكربت الفهرس أسماء السور من Quran.com API عند الحاجة، ويحلل كل صفحة ويتحقق من 6236 آية و114 سورة. Node مطلوب للفحوص أثناء التطوير فقط، ولا يلزم في الموقع المنشور.

يتتبع مدير التنزيل البايتات الفعلية، ويستخدم أربعة اتصالات للملفات الصغيرة واتصالًا واحدًا للملفات الكبيرة. يحفظ كل ملف بعد التحقق من حجمه وبصمته؛ انقطاع الشبكة لا يمحو الملفات المكتملة. عند فتح التطبيق ثانية يفحص وجود الملفات وبيانات التثبيت، ويعرض تنزيل الناقص فقط. يطلب مساحة تخزين دائمة إذا أتاحها المتصفح، ويتحقق من المساحة المتاحة قبل البدء. قد يمحو Safari التخزين المحلي تبعًا لسياساته، وفي هذه الحال يعود الزر إلى وضع التحميل.

## طريقة العمل

يُبقي التطبيق مجموعات علامات الآيات وعناوين السور والبسملة ظاهرة. يخفي مجموعات الكلمات `md-word-*` مع المحافظة على هندسة SVG. لكل كلمة مفتاح من السورة والآية وترتيب الكلمة. تظهر الكلمة عند مطابقة لفظها، وتوضع علامة حمراء في موضع الكلمة المخطوءة، ثم تُكشف بعد ثلاث محاولات مسجلة. التكرار يبرز الكلمة الزرقاء مؤقتًا. تنتقل الصفحة تلقائيًا مع استمرار بث الميكروفون.

ينتقل الصوت من `AudioWorklet` إلى عامل Web Worker بعينات أحادية 16 كيلوهرتز. يخرج العامل خصائص log-mel من 80 مرشحًا بنافذة 25 مللي ثانية وخطوة 10 مللي ثانية، ثم يشغّل مُشفّر ONNX ومفكك RNNT. يفحص التطبيق فرضيات متتابعة قبل اعتماد الكلمة، ثم يقارنها بنافذة محدودة حول الموضع الحالي. لا يستخدم Web Speech API أو تقدمًا وهميًا. لا يقدّم التقرير أحكامًا في المد أو الغنة أو المخارج؛ هذه تحتاج نموذجًا صوتيًا مخصصًا وتحققًا مستقلًا.

## Firebase

يستخدم التطبيق إعدادات Firebase المحددة في الطلب، ويسجل دخولًا مجهولًا ثم يحفظ التقرير تحت `recitationSessions/{uid}/{sessionId}`. يجب في لوحة Firebase:

1. تفعيل **Anonymous Authentication**.
2. إنشاء **Realtime Database** في المشروع نفسه.
3. نشر قواعد `firebase-rules.json`. تحصر القراءة والكتابة في صاحب `uid`، وتمنع باقي المسارات.

إذا تعذر Firebase، يبقى التقرير معروضًا ومحفوظًا محليًا في المتصفح. لا تُحفظ عينات الميكروفون في قاعدة البيانات.

## الفحص والتشخيص

يفعّل `?debug=1` لوحة معلومات تتضمن مستوى الصوت، عينة الصوت، فرضية التعرف، زمن الاستدلال، الكلمة المتوقعة، ورقم الصفحة. الفحوص المتاحة:

- `node tests/logic.test.mjs`
- `python3 tests/index_integrity.py`
- `node tests/assets.test.mjs`
- `node tests/download.test.mjs`
- `node tests/asr-smoke.mjs /path/to/16khz-mono-float32.f32` لاختبار ملف تلاوة حقيقي.

نجح اختبار النموذج محليًا على مقطع تلاوة لسورة الإخلاص، لكن يحتاج التحقق النهائي من الميكروفون، التخزين، وزمن الاستجابة إلى تجارب فعلية على iPhone Safari وAndroid Chrome؛ الأداء يختلف حسب ذاكرة الجهاز وسرعة المعالج.
